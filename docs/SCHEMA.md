# 数据模型

| 表 | 粒度 | 主要用途 |
|---|---|---|
| `properties` | 一行一个商业项目 | 城市、区域、项目类型和可出租面积 |
| `units` | 一行一个铺位/单元 | 面积、楼层、业态和当前状态 |
| `tenants` | 一行一个租户 | 租户名称、行业、等级和注册城市 |
| `leases` | 一行一份租约 | 租期、月租金、租户和铺位关系 |
| `rent_payments` | 一行一份租约的一个账期 | 应收、实收、到期日和付款状态 |
| `operating_expenses` | 一行一个项目、月份、费用类别 | 实际费用和预算费用 |

## 关键关系

```text
properties 1 ── n units 1 ── n leases n ── 1 tenants
                              │
                              └── 1 ── n rent_payments

properties 1 ── n operating_expenses
```

## 业务约束

1. 每个铺位属于且只属于一个项目。
2. 项目内铺位面积之和不能超过项目可出租面积。
3. 同一铺位在同一日期最多有一份有效租约。
4. `2026-09-01` 有有效租约的铺位状态必须为 `occupied`，否则为 `vacant`。
5. 租金账单只能出现在租约有效月份内。
6. `amount_paid` 不得为负，且第一版不允许超过 `amount_due`。
7. 付款状态必须与应收、实收和到期日一致。
8. 运营费用和预算费用均不得为负。

## 当前简化

- `units.status` 是 `2026-09-01` 的快照，历史出租率必须根据租约起止日期计算，不能用该字段回推历史。
- 合成数据未单独建模后续催收与跨账期核销；部分付款和逾期余额会保留在原账单上。
- “城市”默认指项目所在城市 `properties.city`；租户注册城市是不同维度。
