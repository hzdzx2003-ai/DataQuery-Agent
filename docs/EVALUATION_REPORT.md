# DataQuery Agent 评测报告（公开草稿）

> 历史记录 · 2026-09-22 / evaluation v2.0.1。下文保留该阶段原始表述；最新版代码、结果与范围见[版本与数据索引](VERSION_INDEX.md)，演进关系见[迭代历史](ITERATION_HISTORY.md)。


## 1. 评测对象

DataQuery Agent 是面向商业地产运营的个人 Text-to-SQL 原型。评测分别观察业务行为路由、SQL 安全执行、结果正确性和纠错链路，不把“SQL 能运行”当作“业务答案正确”。

## 2. 数据与版本

- 6 张独立设计的商业地产表，1,359 行确定性合成数据。
- evaluation v2.0.1：24 题，其中 16 条开发题（development）、8 条冻结留出题（holdout）。
- 行为分布：8 执行、2 披露后执行、8 澄清、6 拒绝。
- Gold SQL：每道题人工核对的标准查询及其标准结果，用于离线比对模型输出。
- v2.0.1 SHA-256：`7c8ddd95e4a674bfa0a069412ae3ce8433f4ed8caafbf65b6569fb1f8d6a248c`。
- v2.0.0 已归档；v2.0.1 只修正 D2-003 development Gold 的多余输出列，holdout 未改。

## 4. 关键问题案例（Bad Case）

### 月份存储格式

Phase 2B 的 D2-004 首次使用 `2026-08` 匹配按月字段，返回空结果。补充“月份存为每月第一天 `YYYY-MM-01`”的字段约定后，重新生成 SQL 并与 Gold 匹配。该结果证明字段存储约定必须显式提供，但不是自动 SQL 纠错成功样本。

### D2-003 评测假阴性

Phase 3 首次离线比较把 D2-003 判为不匹配。模型输出了题目要求的租户、项目和到期日；旧 Gold 额外输出内部 `lease_id`。项目归档 v2.0.0，仅修正 development Gold 投影并冻结 v2.0.1，然后使用原 Trace 重新评估，结果匹配。Gold 差异没有被反馈给模型，也没有触发线上重试。

## 5. 尚未验证

- 8 条 holdout 尚未运行，不能报告 holdout 准确率。
- 5 条端到端真实运行全部首次成功，因此真实多轮纠错样本数为 0；只能说明纠错骨架通过构造场景的自动化测试。
- 当前数据缺少“历史查询时仍有效、但当前快照已过期”的租约，暂时无法揭示错误使用当前 `lease_status` 过滤历史出租率的问题。
- 没有真实企业用户试用数据，不能宣称生产可用、企业级或业务效率提升。

## 6. 公开表述边界

可以说：独立设计并实现；仅开发题的真实运行 5/5；只读防护和结构化 Trace；评测版本与修订可审计。

不能说：通用准确率 100%；holdout 已验证；纠错成功率；生产落地；优于商业产品。
