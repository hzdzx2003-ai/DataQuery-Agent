# Phase 3 离线链路骨架

> 历史演示版本文档。下文保留该阶段原始表述；最新版代码、结果与范围见[版本与数据索引](VERSION_INDEX.md)，演进关系见[迭代历史](ITERATION_HISTORY.md)。


Phase 3 把现有组件串成可追踪的执行链：

1. `QueryRouter` 返回执行、披露、澄清或拒绝。
2. `clarify/reject` 在类型闸门处停止，不能进入 SQL 生成。
3. `SqlGenerator` 接口产生 SQL 候选；当前测试使用本地假模型，不调用外部 API。
4. `ReadOnlySqlGuard` 做语句预检，并通过只读连接和 authorizer 执行。
5. 明确区分预检失败（`precheck`）与数据库执行失败（`execution`），并归一为稳定的错误类型。
6. 只有预检或执行报错才触发修正；反馈始终要求保留原业务指标、过滤条件和分组，最多三次，避免失控循环和不可预测费用。
7. 每次尝试记录 SQL、状态、失败阶段、错误类型、耗时、列名、行数，以及该失败是否在后续尝试中恢复。
8. `JsonTraceStore` 可将完整尝试序列原子写入 JSON；Trace 不包含 API Key、请求头或 Base URL。

## 结果边界

- SQL 成功执行但返回 0 行，是一次成功执行，不自动重试；应由后续结果解释层向用户说明。
- “SQL 可执行但业务结果错误”不能靠数据库错误发现。与 Gold SQL/Gold 结果的差异只用于离线评测，绝不能作为线上重试信号。
- 三次均失败时，系统保留全部失败记录并返回诚实的安全失败说明，不伪造答案。

当前阶段只验证链路控制与 Trace，不运行 Qwen，不运行 v2 holdout。空结果解释和可执行但错误的结果层检测仍属于后续能力，不在本阶段伪装成已完成。
