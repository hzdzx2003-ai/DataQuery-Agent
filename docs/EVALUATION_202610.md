# DataQuery：自然语言问数评测（2026-10）

## 产品成果

面向非专业业务用户，将自然语言转换为结构化查询计划，由固定指标公式与参数化 SQL 执行。迭代重点是减少过度澄清，保留时间、筛选、分组、排序及组内前 N，并对真实口径歧义给出可操作的追问。

## 100题如何测量

版本 `nl-v3-diagnostic100-20261005-1`，模型 `qwen3.7-max`，thinking budget 4096。100道开发评测题包括70道明确查询、20道必要澄清、10道库外拒绝；完整通过分别为70、13、10。评价同时检查目标、时间、筛选、分组排序、业务口径和回复一致性，部分正确不计通过。项目维护者逐题复核，103次请求含3次契约纠错。

随后将保存的计划送入 `nl-v3-fixed-backend-1`：58道数值指标与12道实体清单均匹配参考结果。后端采用固定公式、标识符白名单和绑定参数，不让模型自由编写 SQL。这是已有开发集的模型实测与离线执行回放。

## 迭代提升如何计算

取早期运行中传输中断前全部57个已完成语义案例，包含解析失败；两版题面与 Gold 相同。完整通过41→54，相对提升 `(54-41)/41 = 31.7%`，增加22.8个百分点。该组同时包含普通查询、分组查询、澄清与拒绝，体现整体版本升级。传输失败的下一题及未运行题不参与语义配对。

严格判定要求候选方案不承诺未支持的计算。平均方式案例若仅按“问对歧义”宽松计分，旧版为42题通过，对应提升28.6%。这是回顾性同题比较，不是独立未见集或单一代码改动的因果实验。

## 响应速度如何测量

同20题、同模型及提示，比较思考开启/关闭；两组均17/20完整通过。计时包括模型处理、契约纠错与本地后端，不含页面加载及交互。另一次完整100题关闭思考测试为91/100，平均模型任务耗时5.09秒。因此93%的质量配置与关闭思考的速度配置分别报告。
